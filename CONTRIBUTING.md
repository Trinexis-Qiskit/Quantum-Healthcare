# Trinexis Qiskit Fall Fest 2026 — Submission Guidelines

This repository is used to collect individual project submissions for the hackathon. Please follow the instructions below carefully to ensure your submission is complete and eligible for evaluation.

## 1. Fork the Repository

1. Open the official GitHub repository for your selected hackathon domain.
2. Click the **Fork** button in the top-right corner.
3. Create a fork under your personal GitHub account.
4. Clone your fork or use the GitHub web interface to make changes.

**Important:** Do not create your submission directly in the original repository.

## 2. Create Your Submission Folder

Create a folder inside the `submissions/` directory using the following naming convention:

```text
GITHUB_USERNAME_NAME_FALL_FEST_2026
```

**Example:**

```text
quantumdev99_Sidharth_FALL_FEST_2026
```

Replace `quantumdev99` with your GitHub username and `Sidharth` with your name.

### Naming Rules

- Use your own GitHub username.
- Include your name for easy identification.
- Use underscores instead of spaces.
- Do not include email addresses in the folder name.
- Use the suffix `FALL_FEST_2026` exactly as specified.
- Create only one submission folder per participant in the selected repository.

## 3. Include All Required Deliverables

Your submission folder must contain the following files and directories:

```text
submissions/
└── GITHUB_USERNAME_NAME_FALL_FEST_2026/
    ├── README.md
    ├── src/
    ├── report.pdf
    ├── presentation.pptx
    └── demo-video-link.md
```

### Required Files

| File | Requirement |
|---|---|
| `README.md` | Provides an overview of the project, problem statement, proposed approach, and setup and execution instructions. |
| `src/` | Contains the source code, notebooks, and other relevant implementation files. |
| `report.pdf` | Contains the project report, including the solution, methodology, results, and conclusions. |
| `presentation.pptx` | Contains the final presentation slides. |
| `demo-video-link.md` | Contains the public YouTube URL of the demonstration video showcasing the project. |

You may include additional files or directories if they are necessary for your project.

**Demo video requirements:**

- Upload your demonstration video to YouTube.
- Set the video's visibility to **Public**.
- Include the public YouTube video URL in `demo-video-link.md`.
- **Only public YouTube videos are accepted.** Unlisted videos, private videos, and videos hosted on other platforms are not permitted.
- Ensure that the video link works and the video is accessible to the judges.

## 4. Prepare Your Project README

Your submission's `README.md` must include the following information:

- Participant's name and GitHub username
- Selected hackathon domain
- Project title
- Problem statement
- Proposed solution and quantum computing approach
- Technologies, libraries, and frameworks used
- Instructions for installing dependencies and running the project
- Results, findings, and limitations
- Links to the presentation and demo video
- References and acknowledgements, where applicable

## 5. Commit and Push Your Changes

After adding all the required files to your submission folder:

1. Commit your changes to your fork.
2. Push the changes to your fork if you are working locally.
3. Verify that all files and links are accessible.
4. Ensure that your code is well-organised, properly documented, and ready for evaluation.

## 6. Submit a Pull Request

Once your submission is complete:

1. Open your fork on GitHub.
2. Select **Contribute → Open pull request**, or use the available option to create a pull request against the original repository.
3. Set the original repository as the base repository.
4. Select the appropriate base branch.

Use the following format for your pull request title:

```text
Submission: GITHUB_USERNAME_NAME_FALL_FEST_2026
```

In the pull request description, include the following details:

- Project title
- Selected hackathon domain
- A brief project summary
- Links to your presentation and public YouTube demo video

Submit your pull request before the official deadline.

**Your pull request serves as your official submission for evaluation.**

## 7. Submission Checklist

Before opening your pull request, confirm that:

- [ ] You have forked the correct domain repository.
- [ ] Your submission folder follows the required naming convention.
- [ ] Your source code and notebooks are included.
- [ ] Your project README is complete.
- [ ] Your project report (`report.pdf`) is included.
- [ ] Your presentation (`presentation.pptx`) is included.
- [ ] Your demo video is uploaded to YouTube and set to **Public**.
- [ ] Your `demo-video-link.md` contains the correct public YouTube URL.
- [ ] Your demo video link works and is accessible to the judges.
- [ ] Your code includes the necessary setup and execution instructions.
- [ ] Your pull request targets the original repository.
- [ ] Your submission complies with the hackathon rules and deadline.

## 8. Evaluation and Review

The organisers will evaluate submissions based on completeness, technical implementation, originality, relevance to the selected domain, and the applicable judging criteria.

Opening a pull request does not guarantee acceptance of your submission. The organisers may request corrections or additional information before completing the review.

Please keep your pull request and all supporting links accessible until the evaluation process is complete. Your YouTube demonstration video must remain public throughout the evaluation process.

## 9. Need Help?

If you encounter any difficulties with forking the repository, preparing your submission, or opening a pull request, please contact the hackathon organisers through the official Trinexis communication channels.

Good luck, and happy quantum computing!
